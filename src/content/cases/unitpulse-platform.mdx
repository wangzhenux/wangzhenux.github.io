<section id="p8" data-reveal>
  <PartHeader num="11" title="Reflection" />
  <Reflection>
    <ReflectionCard label="On the real problem" heading="The system was the design problem">
      The interesting problem was never one screen. It was turning 3 fast,
      separate bets into one coherent platform without a rewrite or a drop in
      quality, because that's what customers were asking for.
    </ReflectionCard>
    <ReflectionCard label="On the industry" heading="Renters aren't one audience">
      Renters don't want the same things, so the AI shouldn't hand them the
      same answer. The segment work is where the product earns trust: a virtual
      tour for someone across the world, an honest alternative when a box isn't
      ticked.
    </ReflectionCard>
    <ReflectionCard label="On what I got wrong" heading="Spec first, then let AI build">
      Early on I handed AI coding an underspecified design language and took
      the speed. The drift and rework that followed taught me the order:
      write the system down first — a design.md, tokens, tested components —
      then let AI build against it. AI helps me try ideas and build faster. I
      still need to define the behavior, review the details, and test whether
      it works for the person using it.
    </ReflectionCard>
    <ReflectionCard label="What I'd fix next" heading="Recovery at the edges">
      Two missed keypresses at the phone menu still end a call; they should
      reach voicemail. And text written by code should answer in the renter's
      language, the way the AI's own replies do.
    </ReflectionCard>
  </Reflection>
</section>
