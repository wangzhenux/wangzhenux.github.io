Duration tokens
Token Value When to use
--dur-snap 80ms Below perception threshold. Color swaps on hover (button fills, nav items, table rows). Never use for positional motion.
--dur-brisk 120ms Micro-interactions. Focus ring fade-in, toggle thumb travel, chip/badge appearance. The workhorse for small elements.
--dur-standard 200ms General UI transitions. Popovers, combobox menus, tooltip reveal, skeleton-to-content, card entrance animations.
--dur-enter 280ms Overlays arriving on screen. Drawers, modals, toasts. Long enough to feel intentional; short enough to not block.
--dur-deliberate 400ms Reserved. Page-level reveals or orchestrated sequences (e.g. KPI dashboard loading in stages). Use sparingly.

Principles
Do
  • Use transition for state changes; animation only for entrances and continuous loops.
  • Keep duration proportional to distance — small element, short time.
  • Always declare prefers-reduced-motion fallbacks for any animation class.
  • Use --anim-delay to stagger siblings rather than duplicating keyframes.
  • Animate opacity + transform together — GPU-composited, no layout thrash.
Don't
  • No skeleton shimmer on data that loads in under 300ms — flash is worse than nothing.
  • No page transitions or route-change animations.
  • No card-entrance waterfalls on every page load — reserve for first-paint async reveals.
  • No bouncy spring / elastic easing — this product reads like a newspaper, not a game.
  • Never animate width, height, or top/left — use transform instead.
The system intentionally ships with no page transitions, no card entrances on navigation, and no skeleton shimmers for fast responses. Motion is information about state change — not decoration. Every animation should answer the question "what just happened?" and then get out of the way.
